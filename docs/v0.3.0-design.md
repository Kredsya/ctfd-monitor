# v0.3.0 복기와 제품 설계

v0.2.0 감사의 83개 테스트에서 실패 단언 24건이 나왔다. 핵심 원인은 원본의 필수 작업 흐름을 범용화 과정에서 선택 기능으로 바꿔 버린 것, 변경된 구현에 맞춘 테스트만 통과시키고 설치 산출물까지 확인하지 않은 것이다. 토큰 인증 문제도 CTFd의 JSON 헤더 요구를 누락한 클라이언트 문제였으며 해당 수정은 v0.2.0에 이미 포함됐다. 기존 릴리스와 감사 기록을 고쳐 쓰지 않고 이번 버전에서 제품 계약을 복원한다.

## 사용 흐름과 책임

| 사용자가 하는 일 | 제품이 보장하는 동작 | 담당 |
| --- | --- | --- |
| clone 후 install.py 실행 | 비밀 입력 숨김, 인증·API·필수 파일 검사, 성공 후 설정 교체 | installer, client, assets |
| 모니터 실행 | 문제 설명·첨부·AGENTS·보조 스크립트 준비, 중복 실행 방지 | app, assets |
| 문제 폴더의 22.sh/25.sh 실행 | 제공된 원본과 동일한 4/10 창, F2/F3, 재접속 시 작업 유지 | 배포된 두 스크립트 |
| LLM과 대회 전 커스텀 | TOML과 지침 템플릿으로 수정, 기존 AGENTS 보존, 소스 스크립트 선택 순서 공개 | config, assets, README |
| 서버 장애·대회 종료·재시작 | 마지막 정상 데이터를 유지하고 조회 상태와 구분해서 표시 | app의 저장·polling |
| 다운로드·압축 도중 중단 | 부분 파일 정리, 원본 백업, 실패를 완료로 기록하지 않음 | app의 전송, archives |
| 업데이트·배포 | clone뿐 아니라 sdist 설치와 설치된 wheel의 작업 폴더까지 검사 | 테스트와 CI |

`assets`는 필수 스크립트 목록·탐색·설치 검사와 기본 작업 지침을 한곳에 둔다. 기본 제공 파일을 잃어도 성공으로 보이게 하는 빈 기본값을 제거한다. 명시적 `helpers=[]`는 모니터만 원하는 사용자의 선택으로 유지한다. 임의 홈 폴더의 오래된 스크립트는 가져오지 않는다. clone의 수정 파일과 wheel의 패키지 자산은 동일한 테스트 기준으로 검사한다.

기본 지침은 특정 대회, 특정 LLM 서비스, 비밀 값에 의존하지 않는다. 문제 설명은 README에 저장하고 기존 사용자 지침은 변경하지 않는다. KOTH/Codex 통합은 기존 ACDC용 선택 기능으로 유지하며 일반 대회에서 자동으로 활성화하지 않는다.

## 오류와 데이터 보존

- 토큰은 JSON API 조회에 사용하며 로그인 페이지 세션과 혼동하지 않는다. API의 외부 origin URL은 전송 전 거부하고 첨부 redirect에는 기존 인증 제거를 유지한다.
- HTTP 403 자체를 대회 시작 전으로 해석하지 않는다. 서버의 명시적인 대회 기간 코드를 구분하고, 권한 실패는 설치 실패 또는 STALE 상태로 표시한다. probe 역시 필수 API 실패 시 성공 종료하지 않는다.
- LIVE는 실제 조회 성공 뒤에만 표시한다. 빈 대회의 계정 변경도 저장하고, 재시작 시 저장된 문제는 STALE로 복원한다.
- 첨부 이름은 최종 저장 이름을 기준으로 중복을 검사한다. 압축은 내용과 모든 대상 경로를 먼저 검사해 자기 덮어쓰기·링크 이탈을 막는다. 디스크 오류·강제 종료에 대한 파일별 복구는 전체 디렉터리의 원자적 교체와 구분한다.
- 표준 점수판의 score를 사용하고 제공되지 않는 ACDC 지표나 상대 풀이 상태를 추정해서 표시하지 않는다. 시간대 없는 서버 시각은 UNAVAILABLE, 터미널 제어문자는 출력에서 제거한다.

## 검증 원칙

감사 실패를 삭제하거나 skip/expectedFailure로 바꾸지 않는다. 자산 검사를 추가하면서 저장 실패 테스트가 그 검사에서 먼저 종료할 수 있었으므로, fixture에 정상 자산을 준비하고 실제 설정 교체 함수까지 도달했다는 단언을 추가했다. 보조 스크립트 통합 테스트는 fixture 사본이 아닌 배포할 스크립트를 실제 tmux에서 실행한다.

checkout·sdist에서는 실제 PTY로 두 인증 방식의 설치·실행·종료를 검사한다. wheel은 별도 경로에 pip로 설치한 뒤 checkout 밖에서 기본 작업 폴더를 생성한다. 공식 CTFd 3.8.9 컨테이너 검증, 네 가지 회귀 mutation, Python 3.12/3.13 CI를 배포 조건으로 둔다. CI가 통과한 태그에서만 wheel·sdist·체크섬을 GitHub Release에 게시한다.

지원 범위는 Linux/Python 3.12 이상과 테스트된 CTFd API다. 모든 CTFd 플러그인, 실제 마우스·OS 클립보드, 외부 KOTH/Codex 운영 서비스까지 검증했다는 뜻은 아니다. 세부 경계는 테스트 매트릭스에 남긴다.
